# 校园网络服务智能助手——参赛设计文档

## 1. 需求与应用场景

面向在校园网、账号登录和 VPN 使用中遇到问题的学生。现有信息分散在手册、使用说明和常见问题中，用户需要快速定位资料，按步骤排查，并在无法解决时清楚描述问题。系统是辅助工具，不是学校官方报修渠道。

比赛要求作品聚焦垂直场景，使用大模型/AIGC/智能体技术，有创新设计与可演示案例，提交需求、设计、模块和工具说明，提供完整可运行软件及公网访问入口。实际公网地址待部署后填写。

## 2. 设计思路

用户输入问题与已尝试的操作 → 规则分诊识别 VPN、账号或校园网 → 简短描述先追问 → Chroma 检索带来源标签的资料 → Gemini 根据证据生成中文步骤 → 显示文件、页码、来源性质 → 生成可复制的报修摘要。检索无足够官方证据时不生成操作建议，改为引导联系正式渠道。

创新点聚焦于把通用 RAG 问答变成可执行的服务流程：信息补全、资料依据、处理建议、人工升级四环相连。摘要由用户自行复制，系统不假装创建真实工单。

## 3. 功能模块与平台

- 资料导入：PDF/TXT 分块进入本地 Chroma；`data/sources.json` 显式标记 `official` 或 `unverified`，默认未核验。未核验资料可显示为参考，但不能单独驱动故障处理建议；来源文件须经团队审查后才能标为官方。
- 智能分诊：按关键词识别问题类别；症状缺失时追问。
- 证据回答：检索相关片段，Gemini 只依据资料组织步骤；界面显示来源文件与页码。
- 报修辅助：汇总类别、问题、已尝试操作与待处理状态，对常见密钥格式做脱敏。
- 交互与接口：FastAPI 提供 `/api/v1/query`；Streamlit 提供中文演示页。
- 部署：Docker 启动时重建向量索引，在同一容器运行 API 与页面；外部只暴露 Streamlit 端口。

## 4. 演示案例与验收

1. 问“校外无法访问校内网站，VPN 怎么使用？”：展示资料支持的步骤、文件页码和来源性质。
2. 只输入“校园网”：要求补充设备、位置、报错和已尝试操作。
3. 问资料未覆盖的故障：明确资料不足，不编造处理流程；提供可复制摘要。

自动测试覆盖分诊、追问、来源标签、无证据拒答、敏感字段脱敏和 API 合约。正式比赛前应从另一台设备经公网完整演示三例并记录访问地址和截图。

## 5. 限制与后续

现有《北邮网络资源手册》自述非官方，且偏向资源导航。需补充经审核的校园网使用、常见故障与正式报修渠道资料；未提供前不能声称具备官方报修指导。关键词分诊与单次检索适合短期演示，长期运营需要真实服务反馈、文档更新流程和更严格的安全评估。
